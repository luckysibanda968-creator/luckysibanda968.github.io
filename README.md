# City of Bulawayo — Council Facilities Map

A no-build, responsive Leaflet map for exploring facility candidates from the supplied City of Bulawayo cadastral data.

## What is in this project

- `index.html`, `css/style.css`, and `js/`: static, vanilla JavaScript ES modules.
- `data/build_geojson.py`: repeatable Shapefile-to-GeoJSON conversion.
- `data/facilities.geojson`: facility parcel polygons and centroid marker features, generated by the converter.
- `data/cadastre.geojson`: simplified parcel polygons for an optional context layer, generated by the converter.
- `data/facilities_details.csv`: editable facility details keyed by the stable generated ID.

The map uses Leaflet and its marker-cluster/minimap plugins from public CDNs. An internet connection is needed for those libraries, Google Fonts, and online basemaps.

## Data inspection and interpretation

The supplied workspace contains cadastral Shapefiles in nested suburb folders, plus ZIP/RAR archives and CAD drawings. The extracted Shapefiles use WGS 84 / UTM zone 35S (EPSG:32735) predominantly; a smaller set is already in geographic WGS 84. The source schema varies, but commonly contains `NAME`, `USE`, `SUBURB`, `ADDRESS`/`ADDRESS_1`/`ADDRESS_2`, `STAND_NO`, `AREA_M2`, `TP_DRG_NO`, `S_PLAN_NO`, and `PHASE_SECT`.

Facility categories are derived, in order, from matching keywords in `USE` and `NAME`: health, education, parks/recreation, transport, emergency, cemetery, markets, utilities, community, and civic offices. A recorded owner is used as a filter: if an ownership field contains a non-Council owner, that parcel is excluded; where ownership is missing, a facility is included only as a **candidate**, not as a verified City Council facility. The map and its exports disclose that limitation. Status, hours, phone, description, photo, and ward are not supplied consistently; the converter uses `Not available` rather than guessing.

The workspace does not contain a reliable ward-boundary layer. A ward map is therefore shown as unavailable instead of substituting suburb boundaries or drawing invented wards. CAD drawings and water-network line/point layers are not treated as cadastral facility polygons.

The converter scans extracted `.shp` files under the source folder. Extract archives first if they contain additional data you want to include. Identical `.shp` copies in nested folders are skipped; duplicate parcel features are also de-duplicated. Every source file must have a readable projection definition; unknown CRS is an error, not silently guessed.

## Setup and run locally

1. Install Python 3.10 or later.
2. In a terminal at the project folder, install the conversion dependencies:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. Generate the web-map data:

   ```powershell
   python data\build_geojson.py
   ```

   To use a different extracted folder or adjust simplification:

   ```powershell
   python data\build_geojson.py --source "C:\path\to\extracted\cadastre" --simplify-meters 2
   ```

4. Open this folder in VS Code and run **Live Server: Open with Live Server** on `index.html`. Do not open the HTML as a `file://` URL: browsers block the local GeoJSON fetch in that mode.

The converter ignores macOS `._` metadata files, repairs invalid or unclosed polygon geometry, discards empty/non-polygon shapes, computes parcel area in metres, simplifies the cadastre with topology preservation, reprojects output to EPSG:4326, and rounds output coordinates to six decimals. The parcel layer is fetched only when turned on so it does not delay the initial map.

## Add or edit facility information

After running the converter once, open `data/facilities_details.csv`. Each facility has an `id` and source-derived name/category/address/stand/suburb/area. Fill in `ward`, `status`, `operating_hours`, `contact`, `description`, `photo`, or `owner_verification` using verified information, then rerun the converter. Edits are joined back using the stable facility `id` and included in both the marker and polygon properties. Leave unknown values as `Not available`; do not enter personal data without authorization.

To add a facility from the source GIS, update the corresponding parcel attributes (or add a correctly projected Shapefile), then rerun the converter. Use a matching land-use or name keyword in `data/build_geojson.py` to introduce a new category rule. Categories, display colours, map centre/zoom, basemaps, and file paths are in `js/config.js`.

## Deploy

**GitHub Pages:** commit/push the generated GeoJSON files along with the static site, then enable Pages for the branch and folder containing `index.html`.

**Netlify:** deploy the project folder as a static site (or connect the repository). Set the publish directory to the project root; no build command is needed. Include the generated files in the deployment. If the cadastral GeoJSON is too large for your host, omit that optional layer from the published version or tile/partition it in a future data pipeline.

## Before production

Verify ownership and category assignments with City Council, add an authoritative ward-boundary dataset, and populate operational details from an approved source. Check source-data licensing, privacy, and publication permissions, especially before publishing detailed parcels. The map is informational and does not replace official Council records.
